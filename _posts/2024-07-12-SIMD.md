## Background
<!-- begin_excerpt -->

대부분의 프로세서는 일반적으로 데이터를 스칼라(scalar) 단위로 처리하도록 설계되어 있고,

<!-- end_excerpt -->

이러한 처리 방식을 SISD(Single Instruction Single Data)라고 부른다.

> <font size="2"> 
> 스칼라는 단일 데이터 값으로 하나의 정수, 하나의 부동 소수점 수 등을 일컫는다.
> </font>

고수준 프로그래밍 언어도 이에 맞춰 스칼라 단위로 데이터를 처리하도록 설계돼 있는데, 컴파일 과정에서 고수준 언어의 문법은 대부분 SISD 방식의 기계어 명령어로 변환된다.

```c++
    int a[3] = { 1, 2, 3};
    int b[3] = { 4, 5, 6};

    int c[3] = a + b; // compile error (SIMD doesn't work this way)

    int d[3];
    for(int i = 0; i < 3; i++) {
        d[i] = a[i] + b[i]; // ok (This is standard scalar (SISD) operation)
    }
```

SISD 방식은 위의 코드처럼 스칼라 단위의 데이터 처리만 가능하고 벡터 단위의 데이터 처리는 불가능한데 이런 벡터 단위의 데이터 처리를 가능케 해주는 방식을 SIMD(Single Instruction Multiple Data) 라고 한다. 한편, GPU는 태생부터 SIMD 기반으로 설계 되었고 SIMD 처리 방식을 보면 GPU 동작 방식을 이해하는데 도움이 된다.

> <font size="2"> 
> 요즘 거의 대부분의 프로세서는 SIMD 명령어 집합을 제공한다. <br>
> </font>

고수준 언어에선 직접적으로 SIMD 문법을 제공하지 않는다. 고수준 언어에서 프로세서 제조사의 SIMD 기능을 사용하려면 두 가지 다른 방법을 통하여 사용 가능하다.

첫째는 제조사의 SIMD 기계어를 직접 고수준 언어 안에 작성하여 사용하는 방법이 있다. 하지만 이 방식은 고수준 언어의 컴파일러가 SIMD 기계어에 대한 제어권 없이 분리된 상태로, 프로세서의 SIMD 기계어가 변경되거나 업그레이드되었을 때 문제가 되거나 최적화 이슈에 대응할 수 없다.

두 번째는 컴파일러가 제공하는 SIMD 전용 built-in 함수를 사용하는 방식으로 컴파일러 내부에서 SIMD 기계어를 호출하고 사용자에겐 built-in 함수를 제공하는 식이다. 이러한 방식은, 컴파일러가 프로세서의 SIMD 기계어에 대한 제어권을 가져 SIMD 기계어가 변경되거나 업그레이드되었을 때 대응할 수 있다.

참고로, 이런 built-in 함수를 intrinsic 함수라고 부른다.

## Vectorize 

스칼라 데이터 방식의 코드를 intrinsic 함수를 사용하여 벡터화 처리를 하면 상당한 성능 효과를 기대할 수 있다. 이는 성능 측정을 통해 스칼라 방식과 비교를 하지 않더라도, 한 개의 명령어로 여러 개의 데이터를 동시에 처리한다는 점에서 직관적으로 그 효과를 예상할 수 있다. 한편, 스칼라 데이터를 벡터화 방식으로 변경할 때, 벡터 데이터의 요소들이 서로 다른 실행 경로(Execution Path)를 가지게 되면 다양한 복잡한 상황을 고려하여 변경해야 한다.

아래서 몇 가지 구체적 예시를 SSE2 intrinsics 함수를 사용하여 벡터화해보고 그 과정에서 발생할 수 있는 주요 이슈들을 살펴보자.

### Basics

앞에서 컴파일 에러가 났던 배열 덧셈을 SSE2로 옮겨 보자.

```c++
#include <emmintrin.h> // SSE2

    int a[8] = { 1, 2, 3, 4, 5, 6, 7, 8 };
    int b[8] = { 8, 7, 6, 5, 4, 3, 2, 1 };
    int d[8];

    for (int i = 0; i < 8; i += 4) {
        __m128i va = _mm_loadu_si128((const __m128i*)&a[i]);
        __m128i vb = _mm_loadu_si128((const __m128i*)&b[i]);
        __m128i vd = _mm_add_epi32(va, vb);
        _mm_storeu_si128((__m128i*)&d[i], vd);
    }
```

`__m128i`는 128비트 레지스터 하나를 뜻하고, 32비트 int 네 개가 들어간다. 반복문이 한 번 돌 때 네 개씩 더해지니 스칼라 버전보다 반복 횟수가 1/4로 줄어든다.

> <font size="2">
> loadu의 u는 unaligned로, 주소가 16바이트 정렬되어 있지 않아도 읽을 수 있다. <br>
> 정렬이 보장된다면 _mm_load_si128을 쓸 수 있지만 정렬되지 않은 주소에 쓰면 크래시가 난다.
> </font>

실제 데이터는 길이가 4의 배수가 아닌 경우가 많다. 이때는 4개씩 처리하고 남은 꼬리 부분만 스칼라로 처리하면 된다.

```c++
    int i = 0;
    for (; i + 4 <= n; i += 4) {
        // SIMD
    }
    for (; i < n; i++) {
        d[i] = a[i] + b[i]; // 남은 요소는 스칼라로
    }
```

### Different Execution Paths

덧셈처럼 모든 요소가 같은 연산을 하면 벡터화는 간단하다. 문제는 요소마다 다른 길로 가야 할 때다.

```c++
    for (int i = 0; i < n; i++) {
        d[i] = (a[i] > b[i]) ? a[i] - b[i] : a[i] + b[i];
    }
```

SIMD는 명령어 하나로 네 개를 동시에 처리하기 때문에, 네 요소 중 두 개는 빼기로, 두 개는 더하기로 보낼 수 없다. 그래서 분기하는 대신 두 경우를 모두 계산하고, 요소별로 필요한 결과만 골라 담는다.

```c++
    __m128i mask = _mm_cmpgt_epi32(va, vb);   // a > b 인 요소는 0xFFFFFFFF, 아니면 0
    __m128i sub  = _mm_sub_epi32(va, vb);
    __m128i add  = _mm_add_epi32(va, vb);

    // mask가 1인 요소는 sub, 0인 요소는 add
    __m128i vd = _mm_or_si128(_mm_and_si128(mask, sub),
                              _mm_andnot_si128(mask, add));
```

비교 결과는 true/false가 아니라 비트가 전부 1이거나 전부 0인 마스크로 나온다. 이 마스크로 AND를 하면 원하는 쪽 값만 남고 나머지는 0이 되니, 두 결과를 OR로 합치면 된다.

> <font size="2">
> SSE4.1부터는 _mm_blendv_epi8 하나로 같은 선택을 할 수 있다.
> </font>

여기서 비용을 짚고 넘어가야 한다. 분기가 없어진 대신 양쪽 경로를 모두 실행한다. 경로가 짧으면 문제가 없지만, 한쪽이 무겁거나 분기가 여러 겹이면 버려지는 계산이 쌓여 벡터화 이득이 줄어든다.

앞에서 GPU가 태생부터 SIMD라고 했는데, 셰이더에서 if 문이 비싸다고 하는 이유가 바로 이것이다. 같은 묶음(warp/wave)으로 도는 스레드들이 서로 다른 분기로 갈리면, GPU도 양쪽 경로를 다 돌리고 마스크로 결과를 고른다.
